# Техническое задание для Codex: универсальное нативное приложение macOS

## 0. Роль и порядок работы
Ты — ведущий macOS/Swift-инженер. Разработай самостоятельное приложение macOS с тремя модулями: (1) локальная диктовка, (2) локальный перевод текста/сайтов/PDF, (3) управление сном Mac. Не ограничивайся предложениями и макетами: создай проект Xcode, исходники, тесты, документацию и воспроизводимую сборку. Работай по этапам, проверяй каждую функцию на реальном macOS; не выдавай заглушки за готовый результат. Если разрешения системы или внешние зависимости мешают, обозначь точный блокер и реализуй доступную часть.

## 1. Принципы
- Полностью самостоятельный продукт и исходный код. Handy (https://github.com/cjpais/Handy) — только функциональный ориентир для диктовки и модели, Amphetamine — только функциональный ориентир для предотвращения сна. Не копируй их код, ресурсы, иконки, названия, интерфейсы или фирменные элементы. Не добавляй ссылки/брендинг этих программ в интерфейс.
- Язык реализации приложения — Swift 6, SwiftUI + AppKit для macOS, без Python/Tauri/Rust/постоянного локального HTTP-сервера. Допускаются специально обоснованные бинарные ML-runtime зависимости (например ONNX Runtime с Swift/ObjC API) и нативные вспомогательные компоненты, если необходимы.
- Target: Apple Silicon, в первую очередь MacBook Air M4, 16 ГБ RAM; целевая macOS — актуальная установленная разработчиком, проверить deployment target/API. Не обещать поддержку неподтверждённых версий.
- Полная автономность после однократного скачивания моделей; отсутствие обязательных облачных API, подписок и аккаунтов. Обращения к сети — только явная загрузка/обновление моделей и необязательная проверка обновлений приложения.
- Установка — одно приложение .app (при необходимости с включёнными компонентами/помощником), одна иконка в меню, единые настройки; без обязательной ручной работы с терминалом после установки.
- Обеспечить отдельное, управляемое хранилище моделей за пределами .app с указанием занимаемого места и возможностью смены папки (в том числе внешний SSD); предусмотреть безопасную работу при отключении SSD.

## 2. Функциональные модули

### A. Диктовка (главный приоритет MVP)
- Глобальное настраиваемое сочетание клавиш для начала/окончания записи; поддержать режим удержания клавиши и toggle, если технически возможно.
- Запись микрофона: AVAudioEngine/AVFoundation, индикация записи и обработки без перехвата фокуса активного приложения.
- Локальное распознавание русской речи и вставка результата в активное редактируемое поле любого приложения, где macOS это позволяет; предпочтительно Accessibility API, резервный вариант вставка через буфер обмена с восстановлением исходного содержимого и фокуса. Не использовать небезопасную постоянную подмену буфера.
- Активная на скриншоте пользователя модель: **GigaAM v3 (русская, около 151 МБ в Handy)**. Именно она — первый целевой вариант. ВАЖНО: не утверждать, что файлы Handy напрямую совместимы. Исследовать формат, лицензию, наличие официальных/доверенных весов и поддерживаемого локального инференса на macOS; проверить точный препроцессинг, токенизацию и декодирование. При наличии надёжной ONNX-реализации использовать ONNX Runtime из Swift, в противном случае выбрать корректный нативный runtime/конверсию с документированием. Число 151 МБ — ориентир из интерфейса, не гарантия размера другой сборки.
- Поддержать каталог моделей и переключение активной без пересборки приложения: скачать, установить, удалить, проверить целостность, выбрать активную, показать языки, размер, статус и совместимость. Проектировать adapter protocol для GigaAM v3, будущих Whisper, Parakeet и других моделей; добавлять только реально интегрированные, протестированные варианты, не фиктивные кнопки.
- Обеспечить качественное распознавание с VAD/обработкой аудио при необходимости; отображать ошибки микрофона, отказа доступа, отсутствующих моделей. По возможности показывать состояние записи в menu bar и ненавязчивом overlay.

### B. Переводчик (второй приоритет)
- Основной режим: выделить текст в любом приложении, нажать настраиваемую глобальную горячую клавишу (рекомендуемый дефолт Cmd+Shift+T), перевести на русский полностью локально.
- Если выделение находится в редактируемом поле и Accessibility позволяет замену — заменить выделенное непосредственно переводом. Если текст только для чтения — **не заявлять о гарантированной замене**: сначала пробовать контекстно доступный метод, иначе показывать компактный overlay, копирование перевода или открывать переведённую копию. Исходный текст не портить.
- Два браузера: Safari и Chrome. Команда «Перевести всю текущую страницу» (рекомендуемый дефолт Cmd+Shift+Y); отображать перевод **внутри страницы** с сохранением структуры/ссылок/изображений и возможностью вернуть оригинал. Предпочтение — без браузерных расширений. Рассмотреть разрешённые macOS Apple Events/Automation и выполнение JavaScript по явному разрешению пользователя (в Safari требуется включить разрешение на JS из Apple Events; в Chrome также соответствующая настройка). Проверить текущую поддержку на установленной версии; без разрешения предоставлять ясный fallback. Не обещать обработку защищённых вкладок, внутренних страниц браузера или сложных cross-origin iframe.
- Безопасный DOM-перевод: обход текстовых узлов с исключением script/style/code/pre, editable полей, парольных/чувствительных данных и пользовательского ввода по умолчанию; batching; кэш, отмена, возврат исходных строк. Не ломать структуру страницы; корректно работать с динамическим DOM настолько, насколько позволяет API.
- PDF: извлекать текст с помощью PDFKit; для сканов использовать Vision OCR офлайн; создавать переведённый просмотр/экспорт PDF с максимально возможным сохранением структуры. Не обещать универсальной подмены текста «на месте» в чужом PDF-просмотрщике. Определить MVP: переведённая копия в собственном viewer; позже наложение поверх страниц и экспорт. Обрабатывать многостраничные документы без зависания UI.
- Переводческий движок — **локальная скачиваемая модель**, не системный Apple Translation как единственный вариант. Исследовать доступную модель en→ru и лицензии/реальные требования к ресурсам. Нужны протокол сменных моделей, загрузка/удаление в UI, определение исходного языка (если поддержано). При отсутствии модели сообщать об этом.
- Если запрашивается возврат оригинала — обеспечить его для браузерной страницы и редактируемого текста, если исходная версия сохранена; явно обозначить область/ограничения Undo.

### C. Управление сном (третий приоритет)
- Аналог полезных пользовательских возможностей Amphetamine, **без копирования кода**.
- Keep Awake: предотвращение простоя/сна с использованием публичных IOKit IOPMAssertion API; при необходимости отдельно поддержать сон дисплея. Режимы: пока включено, на N минут/часов, пока работает выбранное приложение/процесс, при питании от адаптера, до отключения вручную.
- Статус активной сессии в строке меню, таймер и быстрое завершение; корректно отзывать assertion при завершении/сбое/перезагрузке приложения.
- Closed Lid Mode: **отдельная экспериментальная функция**. Встроенные публичные power assertions обычно не отменяют закрытие крышки. Исследовать поддерживаемые механизмы для Apple Silicon/macOS, требования прав администратора и реальные ограничения clamshell mode. НЕ обещать поддержку закрытой крышки без внешнего дисплея, если она не доказана тестами. Не использовать `sudo pmset disablesleep` без явного согласия; избегать постоянного изменения глобальных системных настроек и недокументированных обходов. Если реализуется helper, минимальные привилегии, безопасное восстановление настроек при сбое, отчёт об ограничениях.
- Безопасность: при низком заряде/перегреве деактивировать соответствующий режим, реагировать на отключение зарядки, показывать предупреждение о работе в закрытой сумке. Не подавлять защитные механизмы системы от термического/критического сна.

## 3. UX
- Единая иконка меню macOS, быстрое меню с командами «Диктовка», «Перевести выделение», «Перевести страницу», «Открыть PDF», «Не давать Mac заснуть», «Настройки».
- Основное окно SwiftUI: вкладки «Общие», «Диктовка», «Модели речи», «Перевод», «Модели перевода», «Сон/питание», «Горячие клавиши», «О приложении».
- Русский UI (с возможностью локализации EN в будущем), крупные и понятные индикаторы скачивания/записи/перевода, прогресс, отмена и понятные ошибки.
- Никакого обязательного облака, трекинга или регистрации. Опциональный запуск вместе с macOS через ServiceManagement.

## 4. Проектирование и безопасность
- Архитектура по Swift Packages/модулям: AppShell, GlobalShortcuts, AudioCapture, SpeechEngine, ModelManager, SelectionBridge, TranslationEngine, BrowserAutomation, PDFTranslator, SleepController, Preferences.
- Изолируй тяжёлые ML-операции от main thread, сериализуй управление моделью, освобождай память неактивных моделей, не держи все модели загруженными одновременно. Применять Metal/Core ML/ORT EP только там, где бенчмарки и стабильность подтверждают пользу.
- Права: Microphone, Accessibility; Automation Apple Events для Safari/Chrome только при использовании; пользовательские объяснения каждого разрешения. Не включать лишних entitlements. Предусмотреть ограничения sandbox/signing/notarization и реалистичную схему распространения.
- Никакой сетевой передачи записей, выделенного текста, содержимого страниц и PDF. Логи не должны сохранять содержимое документов/речи без согласия.
- Источники моделей, контрольные суммы, лицензионные условия и адреса скачивания зафиксировать в model manifest; разрешить скачивание только по явному действию пользователя.
- Настройки/модели переживают обновления .app; обработка ошибок диска, сети, разрешений, потери фокуса, конфликта горячих клавиш.

## 5. Этапы и приёмка
1. **Исследование**: проверить API macOS, способы запуска GigaAM v3 локально в Swift, допустимую модель перевода en→ru, Safari/Chrome JS automation, работу closed-lid. Задокументировать доказательства, ограничения и риски. НЕ выдавать гипотезы за факты.
2. **Каркас**: Swift/Xcode .app, иконка в menu bar, Settings, горячие клавиши, разрешения, хранение моделей, тесты.
3. **Диктовка MVP**: установка GigaAM v3, запись, офлайн распознавание и вставка в TextEdit/Safari/Chrome и другие редактируемые поля. Тест: полностью отключить интернет и продиктовать русский текст.
4. **Выделенный перевод**: локальная модель en→ru, глобальная комбинация, замена в редактируемом тексте, fallback для read-only. Тест офлайн.
5. **Браузеры**: перевод полной страницы в Safari и Chrome по команде, восстановление оригинала; тестировать на статических и динамических страницах, документировать проблемные классы сайтов.
6. **PDF**: текстовые PDF и PDF-сканы; offline OCR, preview, экспорт переведённой копии; тест многостраничности и качества верстки.
7. **Питание**: Keep Awake, таймеры, условия, автоматика при батарее. Closed-lid — только после отдельного технического доказательства с тестированием и безопасным возвратом системных настроек.
8. **Качество/релиз**: профилирование RAM/CPU/энергопотребления на Apple Silicon 16 ГБ; permission onboarding; тесты, сборка .app, установка, подпись/notarization по возможности, руководство пользователя.

## 6. Критерии готовности
- Один собственный .app, единый UI и меню; никаких Handy/Amphetamine или их исходников в составе.
- Русская диктовка с GigaAM v3 полностью офлайн; модель можно установить/сменить/удалить через UI.
- Перевод выбранного текста офлайн; замена там, где доступна; правильный fallback для read-only.
- Полная страница переводится в Safari и Chrome без расширений **на подтверждённых тестовых сайтах**, при выданных разрешениях; оригинал восстанавливается.
- PDF открывается, переводится офлайн и экспортируется отдельным документом, с задокументированными ограничениями.
- Keep Awake стабилен, выключается по команде/условию, не оставляет зависших системных запретов сна.
- Closed Lid не считается «готовым», пока не подтверждён на целевом MacBook/macOS и не обеспечено безопасное восстановление системы.
- README содержит команды сборки, перечень разрешений, manifest моделей, функциональные тесты и известные ограничения.
